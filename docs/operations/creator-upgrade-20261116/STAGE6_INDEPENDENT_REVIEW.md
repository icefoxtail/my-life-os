### 실제 음성 엔진 반례의 범위

ABC 반례 당시 파일 SHA-256은 `eec8d23f3d72a7e86c4b00f3bb5bf99bbb34c8638e391aba7e4c5aab77b48260`이다. 제품의 `stopVoice`, `speakDirect`, `speakItemText` 함수를 원문에서 추출하고 실제 공용 음성 엔진과 영어 매핑을 함께 실행했다. 음성 합성 장치 경계는 발화 요청 기록용 대역이었다. 실제 청취 증거가 아니다.

```json
{
  "transform": {"result": true, "utterances": [{"text": "A. Apple.", "lang": "en-US"}]},
  "objectReplay": {"result": false, "utterances": []},
  "phraseForAppleId": ""
}
```

생활 반례 당시 파일 SHA-256은 `f99fd5486f72820a2158591cb010180c8cfec3714736220c7c5a5e04048bd5a7`이다. 기존 작은 DOM/시계 fixture에서 실제 제품 함수와 실제 공용 음성 엔진을 사용했다. 같은 판본에서 여섯 생활 장면의 새 영어 지시 재생은 각각 정확히 한 개의 `en-US` 발화 요청을 만들었다. 이는 첫 조사에서 우려한 영어 매핑 누락이 생활의 지역 번역표로 해결됐다는 범위의 확인이며 음성 품질이나 화면 검증을 뜻하지 않는다.

L2 수정 파일 SHA-256 `555a79b76d2937a61be216ff8e42bb7fc06dcdc253c5d7121fe34609e49d9a00`에서 동일한 실제 엔진 경로를 다시 실행했다. `Apple!`, `Ball!`, `Car!`, `The letters A, B, and C turn into pictures!`, `You met A, B, and C!` 모두 true를 반환하고 각각 정확히 한 개의 `en-US` 발화 요청을 만들었다. 소개·완료의 한국어 원문은 제품 안의 명시적 영어 문장으로 연결됐으며 한국어를 영어 목소리에 넘기지 않았다.

## 읽은 코드에서 일관된 부분

- ABC 그림 선택은 단어 정체성으로 판정하고 세 선택지에 타깃을 한 개만 넣는다. 타깃 위치는 변하며 정답 전 고정 강조가 없다.
- 사물 재생과 명시적 다음 이동이 분리되어 있으며 같은 그림 정답의 반복 선택으로 축하가 누적되지 않게 막는다.
- 생활의 세 가지 유연한 준비 순서는 앞 두 행동의 교환을 허용하고 마지막 행동은 유지한다. 오답 설명은 유지된 준비 카드와 다른, 아직 필요한 준비를 찾는다.
- 고양이의 수동 다음·고양이 변경은 `turnId`를 갱신한다. 이전 화면의 버튼과 타이머는 새 고양이에 적용되지 않게 제한하며 보상은 고양이·상태별 집합으로 보호한다.
- 고양이 돌봄은 오래 기다려도 자동으로 다음 상태나 완료로 넘어가지 않는다. 조기 종료 문구와 완료 보상 조건을 분리한다.

위 항목은 코드 검토 범위이며 원본 브라우저 결과를 대신하지 않는다.
