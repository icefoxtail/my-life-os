# 5단계 검증 원본

이 폴더는 최종 후보와 공개 운영 검증의 원본 보고서, 실제 검토한 PNG 중 대표 이미지, 앞선 후보에서 발견한 실패와 수정 근거를 보존한다.

## 확인 방법

- 각 묶음의 `receipt.json`은 원본 JSON의 상대 경로·바이트 수·SHA-256, 압축본 SHA-256, 보존한 PNG의 원래 위치와 현재 위치를 기록한다.
- `raw-json-reports.tar.gz` 안에는 수집한 JSON 파일의 원본 바이트가 그대로 들어 있다. 묶음을 만들 때 압축본에서 다시 읽어 모든 JSON의 SHA-256을 대조했다.
- `reviewed-png/`는 실제 열어 확인한 원본 중 핵심 화면을 보존한다. 크기 조정이나 이미지 편집을 하지 않았다.
- 원본 검토 기록에 있는 세션의 절대 경로는 당시 경로다. 보존한 PNG의 재배치 경로는 해당 묶음의 `receipt.json`을 따른다.
- 원본 GitHub Actions ZIP의 식별자와 SHA는 각 검토 기록·아티팩트 메타데이터 및 상위 릴리스 증거에 남긴다. 여기 보존하지 않은 전체 PNG는 Actions 아티팩트의 보관 기간을 따른다.

## 이력의 해석

`history/`에는 성공과 실패 보고서가 함께 들어 있다. 실패한 후보를 나중의 성공으로 바꿔 적지 않았다. 마지막 후보의 기능 검사와 main 병합 후 공개 운영 검사는 상위 `STAGE5_RELEASE_EVIDENCE.json`에서 판본·실행 ID·원본 해시로 구분한다.

코드가 변하지 않은 화면의 검토를 재사용할 때에는 실제 파일 바이트와 검사 스크립트의 동일성을 확인했다. 서로 다른 후보의 결과를 합산해 하나의 판본이 전부 통과한 것처럼 표현하지 않는다.

## 검증 범위

수량·상태 모델, 실제 Chromium 공개 메뉴와 버튼, WebGL 메시·카메라, 제공된 소스 바이트, 원본 PNG를 구분한다. 음성 검사는 요청·중단·완료 콜백과 발화 문구를 확인한 것으로 실제 스피커 청취를 뜻하지 않는다. 물리 기기 터치, 시현이의 반응, 설치형 앱의 실제 오프라인 캐시 이관은 별도 미수행 항목이다.

## 기능 판본과 검사 보완 판본

- `candidate/`: PR #46 최종 기능 후보 `6b0a1bb`의 60개 새 시나리오와 76개 기존 수량 놀이 보고서.
- `history/production-f09b827/`: 첫 운영 검사의 세 묶음 성공과 왕국 26/27 실패, 실제 검토한 운영 PNG. 실패는 관측 프레임 부족이며 300 합체 이전에 중단됐다는 사실을 보존한다.
- `frame-observation-fix/`: 실제 수집식에서 추출한 이전/수정 JavaScript와 NodeVM 반례 재현. 이는 합성 시계·RAF 환경의 검사 도구 검증이며 실제 브라우저 실행과 구분한다.
- `repair-candidate/`: PR #47의 검사 보완 후보 `b8f8ca9`에서 60개를 모두 통과한 새 보고서와 두 경계 PNG. 게임 런타임은 첫 기능 병합과 동일하다.
- `production/`: 검사 보완 후 main `7c14faf`의 새 공개 운영 보고서와 새로 검토한 왕국 PNG. 다른 세 게임은 원래 운영 PNG 검토를 코드 동일성에 근거해 재사용하며 정확한 참조를 각 REVIEW에 남긴다.

서로 다른 판본의 전체 Git tree를 같다고 표현하지 않는다. 각 PR의 후보/병합 tree 일치와 PR 사이 운영 코드의 바이트 불변을 구분한다. 전체 완료 판정은 상위 릴리스 증거의 최종 main·run·보고서에 따른다.
