## 공사장 화면 — coding 담당의 교차 검수

첫 실행의 공사장 모바일 세로·가로와 태블릿 원본 화면을 확인했다. 640×360의 목표 영역, 선택 카드, 듣기 미션, 결과·완료 패널이 주어진 장면 및 화면에 표시되는 것을 확인했다. 완료 조작부와 복귀 버튼도 확인했다. 판정은 해당 UI 범위에 대해 PASS다.

기존 일시적인 축하 말풍선은 동작 차량 위에 잠깐 겹칠 수 있다. 이는 상시 목표 장면 잘림과 구분되며, 모든 애니메이션의 무겹침을 검증한 것으로 확대하지 않는다.

## 원시 검사 결과와 재사용 연결 — UI 검수 담당 확인

최종 태블릿 원문에서 4/4·7/7 슬롯 포함, 화살표와 겹침 0, 쉬움 29px·도전 170px 스크롤 최대 위치 도달을 확인했다. 네 직접 터치 제스처는 모두 trusted touchstart/move/end와 scroll 이벤트를 남겼다. 이벤트의 `defaultPrevented=true`는 없었다. GO 실행·완료·홈 복귀·재진입, 소스 불변과 `pageErrors=0`도 확인했다.

최종 채택은 공사장 12행(첫 실행), 코딩의 1024×768 외 다섯 크기 10행(두 번째 실행), 코딩 1024×768 2행(세 번째 실행)이다. 이름은 모두 고유하고 각 채택 행은 PASS다. 관련 제품 소스 해시 및 공사장 흐름·홈 검사 함수도 재사용 판본 사이에서 동일함을 확인했다.

## 최종 제품 범위 — coding 담당 확인

두 제품 파일의 `injectStyle()` CSS를 제외한 바이트가 기준 main과 완전히 같다. `index.html`, `sw.js`, 전체 assets, 표시 helper 및 Pixi는 이번 diff에서 변경되지 않았다. 최신 main 증분은 운영 문서 세 개뿐이다. 승인 자산 76개 해시 일치 및 차량 자산 tree 보존을 다시 확인했다.

기존 38/38·7/7은 과거 운영 검증으로 보존하며, 변경되지 않은 보호 범위의 근거를 재사용한다. 다른 작업이 들어간 최신 main 전체에 새로 실시한 38/38 PASS라고 표현하지 않는다.

검수 과정에서 추가 제품 수정·브라우저 실행·외부 쓰기는 하지 않았다. 이 기록은 물리 기기 검수를 뜻하지 않는다.
