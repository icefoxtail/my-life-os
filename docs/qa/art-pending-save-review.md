# 매직그림판 — 초기 복원 중 저장 경합

## 재현한 결함

기존 `saveWork`는 저장한 PNG를 비동기로 불러오는 중에도 현재 캔버스를 캡처했다. 진입 직후 캔버스는 아직 빈 상태이므로, 이미지 완료 전에 나가거나 탭/배경을 바꾸면 기존 그림 대신 빈 PNG를 저장할 수 있었다.

통합 담당자의 추가 검토 요청에 따라 실제 제품 소스를 Node VM에 읽고 이미지 콜백만 보류했다. `loadWork → restoreFreeImage(완료 대기) → saveWork`와 같은 상태에서 `destroy(false)`를 호출한 두 경우 모두 원본 표식 PNG가 빈 표식 PNG로 바뀌었다. 이미지 완료 이후 저장은 원본을 유지했다.

[수정 전 재현 결과](art-pending-save-before.json)의 소스 SHA-256은 `1d5f2b509054d16c9b76a69cafafa0a4b942833ae953dbaaa524f5a554aa6d9b`다. 이 재현은 콜백 순서·저장값을 검사한 것으로 실제 브라우저 PNG 픽셀 검사와 다르다.

## 수정한 계약

- 복원을 시작할 때 캔버스를 저장 가능한 상태로 보지 않는다. `saveWork`는 기존 PNG를 유지하면서 도안·모드 등의 다른 상태는 계속 저장한다.
- 현재 토큰의 이미지가 현재 캔버스에 실제로 그려진 이후에만 새 캔버스 캡처를 허용한다.
- 초기 복원 중 그림 입력은 보류한다. 불러오기가 끝나면 바로 그릴 수 있다. 초기 로딩 화면에 한 첫 터치가 기존 그림을 지우게 하지 않는다.
- 이미지 디코드 또는 캔버스 그리기 오류에도 원본 PNG를 유지한다. 화면에 새 종이 버튼으로 다시 시작할 수 있다고 안내한다.
- 새 종이는 명시적인 빈 그림으로 저장할 수 있다. 불러오는 중 새 종이를 선택했더라도 되돌리기에는 빈 캔버스 대신 원래 PNG를 보관한다.
- 나가기, 같은 캔버스로 재진입, 새 복원, 오래된 오류/완료 콜백은 토큰과 현재 캔버스로 구분한다.

기존 비동기 복원 검사의 “로딩 중 새 스트로크가 복원을 취소한다” 사례는 이 데이터 보존 계약에 맞춰 “로딩 중 스트로크는 보류하고, 복원 뒤 입력은 정상 수행한다”로 변경했다. 이 변경은 통합 담당자가 명시적으로 승인한 원본 보호 요구를 반영한다.

## 실행 증거

```sh
node scripts/qa-art-pending-save.cjs docs/qa/art-pending-save-results.json
node scripts/qa-art-restore-independent.cjs docs/qa/art-restore-results.json
node --check js/games/art-zone.js
```

[새 저장 경합 검사 결과](art-pending-save-results.json)의 12개 사례와 [비동기 복원 검사 결과](art-restore-results.json)의 6개 사례가 통과했다. 이후 [기존 저장이 남는 쓰기 실패 경합](storage-write-failure-review.md)을 추가 수정하고 두 검사를 재실행했다. 최신 두 보고서의 대상 소스 SHA-256은 `a57a3c7222219e26770f47f6f5a4d05063474991f2ad1e06c4c916a6a4a9d2b5`다.

새 검사는 초기 저장·즉시 종료·정상 복원 후 그리기·로딩 중 터치·디코드 오류·그리기 오류·새 종이 복구·되돌리기·같은 캔버스 복귀·역순 콜백·도안 상태 동시 저장·저장본 없는 첫 방문을 다룬다. 제품 함수 구현을 복제하지 않고 제품 closure에 모의 Canvas와 Image만 제공했다.

실제 브라우저에서 이미지 로딩 지연을 강제로 만든 검사는 수행하지 않았다. 정상 그림판 브라우저 조작 기록과 이 합성 경합 검사의 범위를 구분해야 한다.
