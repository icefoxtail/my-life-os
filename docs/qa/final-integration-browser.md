# 최종 차량 표시·그림판 실제 브라우저 검수

2026-11-07 UTC, 통합 담당자가 공유 Linux Chromium의 탭 39를 직접 조작했다. 제품 모듈 분리 페이지와 실제 메뉴를 담은 반응형 iframe의 결과를 구분한다. 실제 휴대폰/손가락/음성 청취 검증은 아니다.

## 1. 차량의 실제 표시와 세기

`scripts/qa-legacy-play.html`에서 공개 숫자세기 버튼으로 실제 제품 모듈을 열었다. 수량이나 정답 상태를 주입하지 않았다.

- 경찰특공대차 **4대**가 2×2로 표시됐다. 네 SVG 프레임은 `xMidYMid meet`, 동일 viewBox `171 305 735 465`, 가로 약 347.36px·세로 254.4px였다. 이미지 누락 0개. 원본 그림의 비율을 유지하며 같은 크기로 중앙 정렬됐다.
- 첫 차를 더블클릭하고 나머지 세 차를 눌렀을 때 세기 배지는 정확히 **1, 2, 3, 4**였다. 3을 고른 오답은 같은 차량을 유지했고, 4를 고르면 정답 애니메이션과 입력 잠금이 나타났다. 전체 다섯 판 완주로 확대해서 보고하지 않는다.
- 수량을 16~20으로 바꿔 **구급차 18대**를 확인했다. 실제 이미지 18개, 정규화 SVG 18개, 이미지 누락 0개, 내부 홈 버튼 1개. 다섯 열과 열 개 구분선으로 배치됐다.
- 수량을 21~30으로 바꿔 **지게차 21대**를 확인했다. 아래의 점 잘림 수리 후 19·20·21·22·23 선택지의 실제 점 수가 각 숫자와 같고, 모든 점과 버튼이 화면 안에 있었다.

증거: [4대](integration-browser/count-four-final.png), [18대 차량 정렬](integration-browser/count-eighteen-final.png), [21대 및 수정한 점](integration-browser/count-21-dots-final.png). 18대 화면은 선택지 점 잘림을 발견한 시점이며, 차량 정렬 확인과 선택지 최종 수정 증거를 구분한다.

## 2. 실제 메뉴 + 세로/가로 검수

같은 탭을 `scripts/qa-responsive.html`로 이동한 뒤 **실제 홈 → 숫자놀이터 → 몇 대일까?**를 눌렀다. 앞서 고른 21~30 범위가 유지됐고 크레인차 **28대**가 나왔다.

| 관찰 | 390×844 세로 | 844×390 가로 |
|---|---|---|
| 실제 물체 | 28대, 이미지 누락 0개 | 회전 뒤에도 같은 28대 유지 |
| 수량 범위 | 21~30 유지 | 같은 범위 유지 |
| 선택지 | 30·28·26·27·29, 모두 화면 안 | 같은 다섯 숫자, 버튼 하단 102·162·222·282·342px로 높이 390px 안 |
| 점 그림 | 각 숫자와 점 개수 일치. 5열, 2px 간격, 6px 점. 30점도 실제 높이 46px, 잘린 점 0개 | 짧은 가로 화면의 기존 규칙에 따라 점 전체를 숨기고 숫자 선택 유지. 일부 점만 남기지 않음 |

가로에서 실제 28 버튼을 눌러 정답 세기 애니메이션과 선택지 잠금을 확인했다. 이는 한 판의 정답 반응 검수이며 다섯 라운드 전체 완주라고 부르지 않는다.

증거: [세로 28대와 30점](integration-browser/count-28-portrait-final.png), [같은 판 가로 회전](integration-browser/count-28-landscape-final.png).

## 3. 검수에서 찾아 수리한 점 표현 결함

처음 18대 화면에서는 선택지 점을 3열로 만들고 높이 50px에서 잘라 일부 점만 보이는 문제가 있었다. 큰 수 선택지에 다섯 열 배열을 적용하고 잘라내기를 제거했다. 숫자 크기도 조정하여 버튼의 실제 내용이 화면 안에 맞도록 했다.

독립 검수자가 점 생성 수와 판정의 불변을 확인하고 세로 CSS의 기존 3px 간격 우선순위를 지적했다. 선택자를 보강한 뒤 실제 세로 화면에서 **30점·2px 간격·46px 높이·잘림 없음**을 확인했다. [독립 코드 검토](shared-code-independent-review.md)에 최종 소스 SHA와 검토 경계를 기록했다.

## 4. 그림판 최종 복원과 버튼 간격

분리 모듈 페이지에서 그림판을 열자 앞선 전체 앱 검수에서 그린 무지개 획이 그대로 복원됐다. 복원 안내는 숨겨진 완료 상태였다. 되돌리기와 새 종이는 각각 48×48px, x=1251~1299와 1305~1353으로 겹치지 않았다. 모드 전환 뒤 경찰차 도안의 앞서 칠한 검정 경광등도 유지됐다.

증거: [무지개 획·버튼 간격](integration-browser/art-final-toolbar-and-restore.png), [경찰차 도안 복원](integration-browser/art-police-restored-final.png). 분리 하네스의 별도 상단 도구막대 때문에 보이는 캔버스 높이를 제품 전체 화면 레이아웃 판정으로 사용하지 않는다. 전체 앱의 모드 왕복·재진입·새로고침 검수는 [통합 기록](UPGRADE_RELEASE_QA.md)에 별도로 남겼다.
