# 공용 차량 원본 전수 점검

## 범위와 판정

기준 소스는 `359209423327c0162da7e67db72c263db0d97e50`의 `assets/vehicles/vehicles_manifest.json`이다. 현재 통합 매니페스트의 **129개 경로가 모두 존재하고 모두 이미지로 디코딩된다**. 원본 SHA-256, 크기, 실제 형식, 알파 경계, 같은 이름의 대체 파일 후보는 `vehicle-audit.json`에 기록했다.

이번 독립 점검은 **원본을 변경하지 않았다**. 129개 전체를 네 장의 원본 연락시트로 보고, 의심 원본을 확대해서 배경·여백·파편을 확인했다. 사용하지 않은 새 그림으로 정상 원본까지 전부 교체하는 방식은 권하지 않는다.

기준 커밋 원본의 대표 결함은 [확대 비교 그림](vehicle-audit-examples.jpg)으로 함께 보존했다. 이 그림은 정비 전 자료이며, 완료된 수리 결과를 뜻하지 않는다.

| 원본에서 확인한 상태 | 수 | 해당 범위 | 처리 구분 |
|---|---:|---|---|
| 체크무늬가 불투명 픽셀로 들어 있음 | 72 | 공사 확장 18, 공항 9, 농장 9, 항구 9, 도로 9, 동네 18 | 배경 복원 대상 |
| 작은 흰 사각형 안의 차량 + 과도한 투명 여백 | 18 | 특수 차량 전체 | 배경 복원 및 표시 크기 정상화 대상 |
| 차 위에 분리된 원본 조각이 떠 있음 | 2 | `wheel_loader.png`, `concrete_mixer.png` | 검수된 주 객체 경계로 표시 영역 정리 |
| 투명 배경이며 구조상 여백 편차만 있음 | 37 | 소방, 경찰, 구조, 기존 공사, 교통의 나머지 PNG | 원본 보존, 세기 화면의 표시 경계 정규화 |
| **합계** | **129** | | |

57개 파일에 실제 투명 픽셀이 있지만, 그중 특수 차량 18개는 중앙의 흰 사각형이 여전히 남아 있다. 따라서 **알파 채널이 있다는 사실만으로 투명 배경 품질을 통과 처리할 수 없다**. 배경 결함은 90개, 분리 파편까지 포함한 명확한 원본 결함은 92개다. 이 숫자는 수리 완료 수가 아니다.

## 실제 크기가 다른 이유

모든 그림을 같은 CSS 사각형에 `object-fit: contain`으로 넣어도 파일 내부 여백은 남는다. 특수 차량 18개는 이미지 너비·높이 중 큰 쪽 기준으로도 알파 경계가 원본의 약 **45.5~45.7%**뿐이다. 반면 소방 PNG는 대략 91%다. 같은 CSS 크기라면 특수 차량이 절반 크기로 보일 수밖에 없다.

PNG 안에서도 경찰 오토바이 57.7%, 트랙터 60.6%, 닥터카 63.3% 등 차이가 있다. 각 파일의 원본 비율을 보존하면서 **실제로 보이는 객체 경계가 공통 뷰포트에 들어오도록** 표시하는 것이 필요하다. 바닥의 그림자는 의도된 시각 표현으로 남겨도 된다.

`wheel_loader.png`의 검수된 주 차량 알파 경계는 `[117,346,908,780]`, `concrete_mixer.png`는 `[119,314,905,784]`다. 위쪽 파편 때문에 전체 알파 경계를 그대로 쓰면 세기 화면에서 차가 작아진다. 경계 좌표는 `[left,top,right-exclusive,bottom-exclusive]`, 원본은 1024×1024다.

## 같은 차의 깨끗한 대체 파일

전체 `assets`의 같은 stem 후보를 조사했다. 동일 stem이 있더라도 배경 문제를 해결하는 동일 차의 안전한 대체본은 확인하지 못했다.

| 후보 | 확인 결과 |
|---|---|
| 소방 `water_tanker`, `aerial_ladder_truck`의 `fire_special` 대응 파일 | 별도 외형이며 흰 배경이 있다. 원본 대체로 부적합 |
| `assets/abc-phonics/tiles/car.png` | 글자놀이용 그림이며 같은 차량 원본의 정리본으로 간주할 수 없음 |
| `transport/tractor.png`와 `farm/tractor.webp` | 앞 파일은 깨끗한 투명 그림이지만 서로 다른 외형이다. 동일 파일의 재정비본이 아님 |

## 검증 방식과 한계

- 파일 바이트 SHA-256과 Pillow 디코딩으로 경로·실제 형식·크기를 확인했다. 확장자만 보고 형식을 판단하지 않았다.
- 알파 값 16 및 128을 기준으로 비투명 픽셀 경계를 각각 계산했다. 원본 알파 경계는 의미상의 차체 경계와 다르다.
- 알파 연결 요소를 측정해 파편 후보를 찾고 시각 확인했다. 물 분사, 거울, 로터 등 정상 부품도 분리 요소일 수 있으므로 자동으로 작은 요소를 지우는 규칙은 채택하지 않았다.
- 원본 연락시트 4장, 파편·특수차·트랙터 비교 확대 1장, 소방 특수 9종 연락시트 1장을 직접 확인했다.
- 연락시트는 파일 내용 검수다. 실제 브라우저의 배치·클리핑, 새 렌더러의 총량 표시, 휴대폰 실제 터치를 증명하지 않는다.
- 이 독립 검수 환경의 Playwright Chromium은 시작 시 `socket() EPERM`으로 종료됐다. 샌드박스 밖 실행은 승인 정책에 의해 거절됐다. 브라우저 검수는 통합 담당의 별도 제공 브라우저에서 수행하며, 이 점검 결과에 실행하지 않은 브라우저 PASS를 포함하지 않는다.

## 병합 전 확인할 결과

숫자세기의 1·5·9개를 서로 다른 차량으로 확인하고, 같은 종류의 모든 복사본이 같은 실제 크기·바닥선을 유지하는지 본다. 11·15·20개를 추가하는 경우에는 세기 가능한 묶음 배치를 따로 확인한다. 정비한 그림을 사용하는 짝맞추기·주차장·공사장·소방에서도 차량 정체성이 보존되고 잘리지 않아야 한다.

최종 보고는 **조사 수**, **실제 원본 변경 수**, **새 대체 그림 수**, **표시 경계만 정규화한 수**를 분리한다. 원본 배경 결함을 목록화한 것만으로 이미지 정비 완료를 선언하지 않는다.

## 정비 후 별도 읽기 검수

통합 담당자가 변경한 `wheel_loader.png`와 `concrete_mixer.png` **2개**를 새로 열어 직접 확인했다. 두 차량 모두 정체성을 알아볼 수 있는 전체 실루엣과 투명한 외곽을 유지하며, 원래 위쪽에 떠 있던 큰 분리 파편은 보이지 않았다. 흰 사각형이나 체크 배경도 관찰하지 않았다. 새 파일은 모두 1312×1199이며, 개별 SHA-256·알파 경계·바이트 크기는 JSON의 `postRepairIndependentReadback`에 추가했다. 기준 커밋의 129개 원본 기록은 덮어쓰지 않았다.

이 **2개 원본 정비 확인**은 나머지 배경 결함 90개를 수리했다는 뜻이 아니다. 표시 경계 정규화와 실제 브라우저 비율·배치는 별도 통합 검증 대상이다.
