# 숫자 배달 우체국 — 독립 브라우저 조작 기록

## 환경과 판정 범위

2026-11-07 UTC, 제공된 공유 Chrome의 CUA로 `http://127.0.0.1:8771/index.html`의 공개 메뉴를 직접 조작했다. 최초 탭 17의 두 주문 이후 브라우저 복구를 거쳐, 다른 작업자가 UI를 조작하지 않는 순차 검수 탭 34에서 네 연령의 세 친구 배달을 끝까지 확인했다. 기본 화면 캡처는 1363×936이다.

입력은 CUA의 실제 버튼 클릭·더블클릭·스크롤과 브라우저 새로고침이다. 게임 상태를 주입하거나 완료 함수를 호출하여 완주를 대신하지 않았다. `scripts/qa-responsive.html`의 360×640 프레임은 좁은 viewport 검수이며, **실제 휴대폰·실제 손가락·터치 장비·아동 관찰·음성 실청취 기록이 아니다.**

## 네 연령의 전체 배달

각 연령에서 세 친구의 주문을 모두 배달하고 **“세 친구에게 모두 도착!”** 결과를 직접 읽었다.

| 모드 | 직접 배달한 세 주문 | 확인한 결과 |
|---|---|---|
| 4세 · 1~10 | 토끼 공 1, 여우 당근 8, 고양이 곰 인형 1 | 첫 두 주문 뒤 새로고침과 브라우저 복구를 거쳐 마지막 주문까지 완료. [완주 화면](npo-age4-route-complete.png) |
| 5세 · 11~15 | 여우 사과 6+별 과자 9=15, 고양이 당근 6+사과 8=14, 토끼 블록 6+곰 인형 6=12 | 일부 미리 담긴 주문과 빈 주문에서 필요한 두 종류를 각각 채워 배달. [완주 화면](npo-age5-route-complete.png) |
| 6세 · 11~15 | 토끼 블록 15, 여우 사과 13, 고양이 곰 인형 15 | 세 주문 모두 열 개 묶음+낱개로 구성하여 배달. [15=10+5 조작 화면](npo-age6-15-as-10-plus-5.png), [완주 화면](npo-age6-route-complete.png) |
| 7세 · 11~15 | 판다 공 12, 강아지 당근 13, 곰 곰 인형 11 | 두 차의 수량 10+2(같은 주문 재도전 6+6), 7+6, 5+6으로 완료. [완주 화면](npo-age7-route-complete.png) |

따라서 이 독립 조작 기록에는 11·12·13·14·15개 실제 주문과 네 모드 전체 세션 완주가 포함된다. 16~20의 고수량 4세 세로·가로 검수는 통합 담당자의 별도 실제 조작 기록이며 이 표에 섞지 않았다.

## 오답·수정·재도전·상태 보존

| 시나리오 | 실제 관찰 |
|---|---|
| 4세 1개 주문에 빈 상자 확인 | 부족 안내, 완료되지 않음 |
| 1개 주문에 공 2개 싣기 | 과다 안내, 실은 물건 유지 |
| 공 하나 내리기 후 확인 | 1개로 배달·수령 완료 |
| 당근 첫 물건 더블클릭 후 나머지 7개 싣기 | 적재량 8개, 같은 물건 중복 집계 없음 |
| 당근 8개 상태에서 새로고침·메뉴 재진입 | 첫 주문 완료 및 둘째 주문 적재량 8개 보존 |
| 4세 도전 수량을 16~20에서 1~10으로 변경 | 이전 1~10의 완료 두 주문과 마지막 주문을 복원해 이어서 완료 |
| 5세 사과 6+과자 9 주문에 사과 7+과자 8 싣기 | 합계는 15지만 종류별 수량이 달라 배달 거부, “사과를 조금 내려 볼까?” 안내 |
| 사과 하나 내리고 과자 하나 추가 | 6+9로 수정, 같은 주문 정상 완료 |
| 6세 블록 3개를 싣고 다른 친구 주문을 선택한 뒤 돌아오기 | 원래 주문의 블록 3개 보존 |
| 블록 10개 묶기 → 풀기 → 되돌리기 | 총량 10 유지, 되돌리기로 한 묶음 복원. 이후 5개 추가하여 15 배달 |
| 7세 공 12개를 1번 차에만 싣고 확인 | “다른 차에도 실어 볼까?” 안내, 성공 처리하지 않음 |
| 2개를 꺼내 2번 차에 싣기 | 10+2 성공, 결과에 `10 + 2 = 12` 표시 |
| 같은 12개 주문에서 “한 번 더” | 상자를 다시 구성할 수 있음. 6+6으로 배달해 성공, 결과에 `6 + 6 = 12` 표시 |
| 비슷하게 나누기: 당근 13개를 9+4로 구성 | “두 차에 비슷하게 나누어 볼까?” 안내, 성공 처리하지 않음 |
| 당근 두 개를 옮겨 7+6으로 수정 | 13개 배달 완료 |
| 네 모드 전환 | 부모 설정에서 직접 4→5→6→7로 선택. 수량 도전은 연령과 별도 유지 |
| 7세 완료 후 다른 페이지를 통해 우체국 재진입 | 세 주문 완료 상태 및 5+6=11 결과 복원 |
| “새 배달 놀이” 선택 | 완료 창이 닫히고 새 친구 순서·주문이 시작됨 |

같은 주문의 두 유효 해법을 각각 [10+2 결과](npo-age7-first-split-10-plus-2.png), [재도전 6+6 결과](npo-age7-replay-6-plus-6.png)로 보존했다.

## 360×640 프레임 검수

같은 Chrome 탭에서 검수 페이지의 “작은 화면 360 × 640” 버튼을 실제 클릭했다. iframe의 홈→숫자놀이터→우체국 메뉴로 재진입하여 저장된 7세 완료 상태를 확인했다.

- [완료 화면](npo-360x640-restored-complete.png): 제목·분배식·새 배달·재도전·다른 놀이 버튼이 프레임 안에 보임.
- [새 주문 상단](npo-360x640-play-top.png): 주문·친구 선택·물건 창고와 두 차 선택이 보이며, 출발 버튼은 아래에 유지됨.
- [실제 스크롤 후 짐칸](npo-360x640-play-scroll.png): 곰 인형 하나를 싣고 작업 영역을 아래로 스크롤하여 짐칸의 물건을 직접 누를 수 있음. 내리기 후 수량 0 확인, 출발 시 부족 안내.
- [11개 주문 그림](npo-360x640-order-picture.png): 큰 곰 인형 그림 10+1 배열, 닫기·주문 듣기·계속 놀기 버튼이 보이며 “계속 놀기” 실제 클릭으로 복귀함.

관찰한 상태에서는 창고·짐칸·조작 버튼이 서로 겹쳐 입력을 막지 않았고, 작업 영역을 스크롤할 수 있었다. 이 검수는 mouse 클릭과 프레임 크기를 사용했으므로 모바일 브라우저 터치 스크롤 관성·OS 주소창 변화·실제 손가락 정확도를 검증한 것은 아니다.

## 발견해 수정 확인한 UI 결함

초기 배송·결과 레이어 폭이 1363px 화면에서 약 327.5px로 축소되어 가로 스크롤이 생기고 차가 잘렸다. `.npo-root > *`의 중앙 정렬이 절대 위치 레이어에도 적용된 문제를 구현자에게 전달했다. [수정 전 화면](npo-overlay-before.png)을 보존했다.

구현자는 레이어 정렬을 stretch로 수정하고 배송 이동에 CSS keyframes를 적용했다. 순차 검수에서 결과 레이어의 bounding/client/scroll width가 모두 1339px이고, 결과 카드가 화면 중앙에 정상 표시됨을 읽기 전용 DOM 측정과 스크린샷으로 확인했다. 위 네 연령 완주 화면과 작은 화면 결과가 수정 후 증거다.

초기 오답 안내 “공를”도 실제 화면에서 발견했다. 받침에 따른 목적격 조사로 수정됐으며 최신 직접 조작에서는 “곰 인형을 조금 더 담아 볼까?” 등 올바른 화면 문구를 확인했다. 실제 음성 발음을 들은 결과는 아니다.

## 초기 중단 기록과 남은 한계

처음 여러 작업자가 다른 탭을 병렬 조작하던 중 공유 Chromium이 Error code 9로 충돌했다. 사이트 코드에 원인이 있다고 특정하지 않았다. UI 조작을 멈추고 통합 담당자의 복구 후 한 작업자씩 순차 검수로 전환했다. 탭 34의 이번 네 모드 전체 완주와 360×640 조작에서는 추가 충돌을 관찰하지 않았다.

- 초기 탭 17의 좌표 드래그 바깥 놓기는 직후 브라우저 응답이 끊겨 결과 미확인이었다. 이 독립 기록만으로 드래그 취소 PASS를 부여하지 않는다. 통합 담당자는 별도 순차 검수에서 실제 바깥 드롭을 수행했다.
- TTS·이미지·저장 실패 주입, 합성 pointercancel·lostpointercapture 등은 구현 담당자의 별도 실패 fixture 결과다. 위 실제 클릭 결과와 구분한다.
- 실기기 Android/iOS, 실제 touch/pen 입력, 아이가 안내를 이해하고 독립적으로 즐기는지, 음성의 실제 청취 품질은 미실시다.
- 이 기록의 localhost 완주를 main 병합·운영 사이트 배포 확인으로 확대하지 않는다. Git/운영 확인은 통합 담당자의 별도 증거가 필요하다.
