특수차의 흰 사각형은 넓은 투명 여백 안에 실제 픽셀로 남아 있다. 일부의 바퀴/하부가 사각형 경계에서 끊긴다. 배경만 지워도 온전한 차량이 되는지 원본을 개별 확대해 판단한다. 없는 장비 구조를 상상하여 복원했다고 보고하지 않는다.

기존 투명 원본의 바닥 그림자와 소방 물 분사 표현은 그대로 보존한다. `wheel_loader.png`, `concrete_mixer.png`의 1차 교체본도 이번 원본으로 사용하며 다시 만들지 않는다.

## 사용처 조사

- 숫자세기, 짝맞추기, 주차장, 코딩카는 통합 129개 manifest를 읽는다.
- 공사장은 construction 27개를 읽는다.
- 소방출동은 기본 소방 9개와 별도 특수 소방 9개를 읽는다.
- 홈의 기차는 `transport/train.png` 직접 참조다.
- **자동차 정비소는 현재 차량을 인라인 SVG로 그린다.** 이 138개의 공용 래스터를 직접 읽지 않는다. 정비소는 동작 회귀 대상이며 원본 수정 개수에 포함하지 않는다.

현재 `SihyeonVehicleDisplay.apply`는 숫자세기에서 사용한다. 다른 게임에 임의 차량별 확대값을 추가하는 대신, 검증된 공용 가시 경계와 단일 종횡비 변환을 사용하는 방향으로 확인한다.

## 원본 복원 및 비교 원칙

실제 픽셀 편집에는 Imagegen의 background-extraction을 사용한다. 각 원본을 직접 열고 차량색·차종·부품·각도 보존을 명시한다. 생성 후보는 원본과 비교하고, 흰색·어두운색·격자 배경 위의 가장자리와 내부 구멍을 확인한 뒤 적용한다. 파일 형식 변환은 lossless 인코딩만 허용하며 배경제거를 대신하는 임의 색상 키잉은 사용하지 않는다.

원본이 손상됐거나 편집 결과가 원형을 바꾸면 원본을 유지하고 구체적인 보류 사유를 기록한다. 완료 수는 원본 파일 bytes가 바뀐 경우와 표시 코드만 바뀐 경우를 분리한다.
