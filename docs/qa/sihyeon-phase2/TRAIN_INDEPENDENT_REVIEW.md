# 패턴 기차 공작소 — 독립 검수

## 현재 판정

**MODEL PASS + UI 합성 검사 PASS. 브라우저·운영은 이 독립 작업자 기준 NOT_RUN.** 이 판정은 모델의 수학·상태·복원 범위에 한정되며 완제품 승인이나 실제 네 연령 브라우저 완주를 뜻하지 않는다.

- 검수 담당: 독립 검수 C (`/root/independent_qa`)
- 구현 브랜치: `feat/sihyeon-pattern-train-20261108`
- 확인한 초기 원격 체크포인트: `449d33e5bb4e320be02076facff56c2a45b38a75`
- 검수자는 제품 파일·원격 브랜치를 수정하지 않는다.
- 독립 작성 테스트: `scripts/qa-pattern-train-independent.cjs`. 모델 API에 연결했다. 기본 실행은 실제 모델을 검사하며 실패 항목이 있으면 exit 1을 반환한다. `--oracle-only`의 자체 검사 성공은 제품 PASS가 아니다.

## 독립 검수에서 확인할 계약

1. 문제의 실제 표시 단서와 허용 반복 단위를 사용해 가능한 완성 배열을 독립 열거한다. 제품 판정 함수를 정답 생성기로 사용하지 않는다. 단서가 부족하면 모든 타당한 해를 인정하거나 문제 자체를 명확하게 만들어야 한다.
2. 색 이름을 제거하고 기호의 동일성 관계와 놀이 행동을 비교하여 콘텐츠가 단순 색 교체로만 늘어난 것은 아닌지 확인한다.
3. 네 연령의 전체 세션, 오답 보존·수정·꺼내기·교체·되돌리기, 자유 공작의 무채점 계약을 확인한다.
4. 시작·출발·완료·재도전 전이의 중복 실행과 출발 중 입력, 이전 상태 snapshot의 변경 여부를 확인한다.
5. 저장 손상·변조·지원하지 않는 값·진행 중 복원·읽기 성공/쓰기 실패·같은 페이지 메모리 복귀를 구분해 확인한다.
6. 실제 포인터 입력과 제어된 합성 실패를 구분하여 기록한다. 드래그 취소·화면 밖 드롭·두 번째 포인터·방향 변경·종료 후 콜백이 보드를 훼손하지 않아야 한다.
7. 새 메뉴 노출, 서비스워커 자산, 기존 게임 종료 정리를 통합 변경에서 별도로 확인한다.

## 증거 경계

Node 모델 검사, 코드 검토, Playwright/공유 Chromium 브라우저 검사, 실제 휴대폰·물리 손가락·음성 실청취는 서로 다른 범위이다. 실행하지 않은 범위에는 PASS를 부여하지 않는다. 배포·운영 실플레이는 통합 담당자의 별도 증거로 확인한다.

## 모델 첫 실행 — 발견과 수정 요청

실행 명령: `node scripts/qa-pattern-train-independent.cjs --report docs/qa/sihyeon-phase2/train-independent-model-results.json`.

독립 검수자가 제품 구현 및 구현자 테스트와 별개로 작성한 oracle을 사용했다. 가능한 보드는 빈칸의 모든 재료 조합으로 열거하며, 정답은 화면에 보여줄 반복 단위·변환 매핑·명시된 허용 반복 길이로 결정했다. 제품의 `validateBoard` 또는 `candidateUnits`를 정답 생성기로 쓰지 않았다. 별도 oracle의 자체 검증 후 제품 생성기와의 대조도 수행했다.

첫 검사 소스 SHA-256: `ee799e260afb4bde9b4a7daf2325c9aabd5d5880d36ff52dcce66ecf71611655`.

- 문제 ID 20개, 색·동물 이름 교체를 제거하고 행동·규칙 관계·빈칸 위치로 구분한 활동 구조 20개.
- 27개 검사 그룹, 실제 보드 판정 비교 14,684개, assert 호출 1,626회. 총 판정 숫자를 브라우저 클릭 수로 보고하지 않는다.
- 7개 검사 그룹 실패, 20개 그룹 통과. 현재 결과는 전체 모델 PASS가 아니다.
- `a5-aab` 1개, `a5-abb` 1개, `a5-aabb` 3개, `a6-abac` 80개, `a6-abbc` 80개의 잘못된 완성을 정답으로 수락했다. 원인은 객차의 고정 단서만 검사하고 보여주는 반복 단위 또는 변환 매핑을 검사하지 않는 데 있다. 이 다섯 문제의 오수락 합계는 165개이며 검사한 정답의 오반려는 없었다.
- 자유 공작 저장본 `size:4.5`를 복원하면 `RangeError: Invalid array length`가 발생했다. 손상 저장을 예외 없이 거부하도록 요청했다.
- 저장본의 undo history에 있는 `phase`, `taskId`, `departures` 추가 필드가 `undo`의 `Object.assign`으로 상태에 주입됐다. 복원 history를 허용된 `board/seed/chosenPeriod`만으로 재구성하도록 요청했다.

이 세 원인의 결함은 구현 담당자에게 재현 입력과 함께 전달했다. 최초 실패 근거는 [초기 실패 결과](train-independent-model-initial-failures.json)에 보존하며, 수정 뒤 최신 검사 결과는 별도로 기록한다.

### 후속 코드 검토에서 추가한 두 재현

- `free:true`, `theme:'constructor'` / `'toString'` / `'__proto__'`, `taskId:'free-'+theme`인 저장본도 예외를 발생시킨다. 테마 lookup이 객체 상속 속성을 허용하기 때문이다. 별도 그룹으로 자동화했다.
- `a6-copy`에서 ABA를 세 번 복제한 배열의 반복 길이는 3인데 결과 `period`는 2이고, `a7-alternative`에서 ABBA를 복제한 배열의 반복 길이는 4인데 3을 반환한다. 짧은 seed에서 마지막의 불완전한 반복을 허용한 결과를 전체 기차 주기로 사용했기 때문이다. 결과의 `period`가 실제 전체 배열을 반복시키는지 독립 검사한다. 최소 길이를 반드시 강제하는 대신 보고한 길이가 실제로 성립하는지를 검사하여, UI가 복제 묶음 길이를 명시하는 설계도 허용한다.

## 수정 후 모델 재검

수정된 모델 SHA-256: `aff31cb58d8ba2fae9d83e6596e71224aa355ee200d116136d7ebb021bd1c8a9`.

같은 독립 테스트를 다시 실행했다. **29개 그룹 / assert 1,645회 / 보드 판정 14,684개를 통과**했다. 첫 검사 후 발견한 상속 테마 이름과 전체 기차 반복 길이의 재현 두 그룹을 추가했으며, 최초 실패 결과는 변경하지 않았다. 최신 구조화 결과는 [모델 재검 결과](train-independent-model-results.json)다.

- 보여주는 단위와 변환 매핑에 맞지 않는 앞서 발견한 165개 오수락이 모두 해소됐다. 모든 출제 문제의 전수 빈칸 조합 비교에서 새 오수락·오반려는 0개다.
- 네 연령 각 5개, 총 20개 활동을 reducer의 실제 편집/묶음 찍기/출발/도착/수정/재출발 전이로 완료했다. **이는 Node 모델 세션**이며 화면 조작 완주라고 보고하지 않는다.
- 중복 출발과 출발 중 편집은 정지 상태를 훼손하지 않았다. 출발 중 저장복원은 BUILDING으로 돌아와 오래된 타이머를 이어가지 않는다.
- 오답을 보드에 유지하고 교체·꺼내기·이동·스왑·undo할 수 있다. 24개 이력 제한과 이전 상태 불변성도 확인했다.
- 자유 공작의 길이4, 재료4종 모든 256개 완성 배열을 채점 없이 수락한다. 빈칸 안내는 있지만 패턴 정오 채점은 하지 않는다.
- 비정수/범위외/잘못된 타입의 자유 크기, 객체 상속 테마 이름, 잘못된 저장 단서·재료·상태는 예외 없이 거부된다. history의 추가 필드를 통한 상태 변경도 차단됐다.
- ABA 세 번 복제와 ABBA 세 번 복제의 보고 주기가 이제 전체 기차와 일치한다.

다음 검수는 UI에서 보이는 단위·변환 그림이 이 판정 계약과 실제로 일치하는지, 드래그/저장 쓰기 실패/나가기/타이머 취소가 상태를 보존하는지 확인하는 것이다.

## 콘텐츠 중복을 더 엄격히 제거한 하한

색/동물 이름을 없애고 4세 AB 변형 다섯 활동을 모두 하나로 합쳐도, 고정 반복 단위 13종과 직접 복제·같은 재료의 대안 규칙·복수해 완성 3유형으로 **16종**이다. 고정 단위는 AB, AAB, ABB, ABC, ABBA, AABB, AABC, ABCC, ABAC, ABBC, ABA, ABCB, ABACBC다. 따라서 원시 ID 20개만으로 최소 16종을 주장하지 않았다.

## UI 독립 합성 검사 — 실제 closure 실행

독립 작성 `scripts/qa-pattern-train-ui-independent.cjs`가 제품 UI closure에 검사용 참조만 노출하여 Node VM에서 실행한다. 제품 함수를 바꾸지 않으며 제어된 DOM·타이머·저장·음성 fixture를 사용한다. 실제 브라우저 레이아웃·터치·음성 실청취 검사는 아니다.

첫 UI 소스 SHA-256: `a8cd453c3d6bedc7ce26060c8e0150ba3c67df73720608c5f8e554623819fbf8`.

10개 그룹이 통과한 범위:

- 네 연령의 다섯 정거장을 실제 `onClick` 경로의 선택·배치·묶음찍기·출발·도착·다음으로 완주: 합성 세션 4개/출발 20회. 중복 출발은 세지 않았다.
- 생성한 가이드 HTML에 반복 단위·변환 대응·허용 반복 길이·seed 편집칸이 실제 포함된다. 렌더 후 눈에 읽히는 위치/크기는 별도 브라우저 검사가 필요하다.
- 오답 유지, 다른 재료로 교체, 꺼내기, undo, 재시작 확인/취소, 나가기 뒤 보드 보존.
- 팔레트 드래그 성공·객차를 팔레트로 되돌리기, 화면 밖 드롭, pointercancel, capture 상실, 짧은 보조포인터 취소, 중복 pointerup.
- resize/Escape/종료 중 드래그 제거, 페이지 재진입 때 중복 리스너 없음.
- 읽기는 성공하고 쓰기만 12회 거절되는 제어된 저장 오류에서 최신 보드가 메모리에 남고 연령/도전 전환·나갔다 들어오기에서 복원된다. 새 페이지는 실제 성공한 저장본만 복원한다.
- 손상 JSON, 거절된 읽기, 비정수 자유 작업판 저장에서 편집 가능한 새 보드로 복구.
- 숨김 페이지에서 진행중 기차를 정지하고 늦은 도착 콜백이 다른 작업판을 완료하지 않는다.
- TTS reject/throw/undefined/hang/늦은 응답은 그림 안내로 이어지며 음소거를 무시하지 않는다.
- 4세 추천 프로필로 7세 도전 진입이 가능하고, 자유 동물/도형/색 작업판을 서로 보존한다.

### 구현자 자가 발견을 독립 재현한 긴 hold 결함

구현자가 보조 손가락 취소 뒤 700ms 제한만 사용하는 점을 먼저 지적했고, 독립 검수자가 별도 입력 순서로 실제 재현했다. `a4-colors` 객차3에 빨강을 넣고 파랑을 선택한 뒤 빨강 객차를 드래그 → 두 번째 포인터로 취소 → 1600ms 유지 → 두 포인터를 놓음 → native click을 호출하면 원래 빨강이 파랑으로 바뀐다. 취소가 보드에 영향을 주면 안 되므로 수정이 필요하다.

11개 그룹/220 assert 중 이 재현 1개가 실패했다. [첫 UI 실패 근거](train-independent-ui-initial-failures.json)를 보존하고, 최신 [UI 합성 결과](train-independent-ui-results.json)는 수정 후 갱신한다. 이 결함의 최초 발견을 독립 검수자의 발견으로 바꾸어 기록하지 않았다.

추가 CSS 읽기에서 긴 6칸 단위의 손 그림과 가이드 폭, 작은 화면의 객차 꺼내기 버튼 상단 잘림 가능성을 통합 담당자의 실제 화면 검사에 전달했다. 숫자로 추정한 위험을 실제 화면 실패로 단정하지 않았다.

## 긴 hold 수정 뒤 UI 독립 재검

수정 UI SHA-256: `25804a309bc79f71a3837c06b2aff8a709064d069a4b6aa0d3eb12fbe42252a9`.

active pointer 집합과 취소된 제스처 표시를 마지막 pointerup까지 보존하고, 마지막 up 뒤 600ms 동안 뒤따르는 클릭을 막도록 수정됐다. 독립 fixture도 실제 등록 순서인 window capture `otherPointerDown` → container `pointerDown`으로 실행하고 capture 상실 이벤트의 타입을 명시했다. 이 과정에서 제품 코드는 수정하지 않았다.

**12개 그룹 / 230 assert를 통과**했다. 앞서 red가 blue로 변하던 1600ms 보조 손가락 hold는 이제 red를 보존한다. 같은 시간의 resize·blur·Escape 취소도 각각 보존하며, 취소가 끝난 뒤 의도적인 새 탭은 다시 정상 동작한다. 무기한 입력을 잠가 검사를 통과시키지 않았다.

12개 그룹에는 앞서 통과한 합성 4세션/20정거장, 안내 HTML, 오답/수정/나가기, 드래그/꺼내기, 저장 성공·실패·손상, 중단된 출발·늦은 콜백, TTS 실패, 자유 공작 및 추천 나이와 도전 독립성 검사가 모두 포함된다. 최초 긴 hold 실패 근거는 그대로 두고 최신 [UI 합성 결과](train-independent-ui-results.json)만 갱신했다.

실제 사용자 화면의 가이드 폭·꺼내기 버튼·첫 빈칸 이동·작동 애니메이션·세로/가로 배치와 live deployment는 통합 담당자가 수행하는 브라우저 검사 범위다. 이 Node 결과만으로 실제 휴대폰 PASS를 부여하지 않는다.
