# 숫자 배달 우체국 — 독립 수량·상태 검수

## 검수 범위

구현자가 작성한 `js/games/number-post-office-model.js`를 별도로 읽고, 독립 검수자가 만든 `scripts/qa-number-post-office-independent.cjs`로 물체 ID와 위치를 직접 세었다. 모델의 `totals` 또는 `validate`를 정답을 만드는 데 사용하지 않았다. 현재 실행 결과와 모델 SHA-256은 `number-post-office-model-results.json`이 정본이다.

이 검수는 **Node에서 실행한 수량·상태 계약**에 대한 판정이다. 화면 배치, 실제 포인터 조작, 음성 실청취, 모바일 실제 기기, 아동 관찰의 통과를 뜻하지 않는다.

## 확인한 범위

- 4·5·6·7세 각각 목표 1~30을 선택할 수 있다. 600개 미션(4연령 × 30목표 × 5 seed)을 생성하고 필요한 재고·고유 물체 ID·합계를 확인했다.
- 총 19,141회 상태 전이에서 이전 snapshot 불변, 물체 소실/복제 없음, 위치 유효성, 모델 판정과 독립 개수 계산의 일치를 확인했다.
- 7세 두 차에 나누는 260가지 구성을 확인했다. 자유 분배는 합계와 두 차 사용 조건에 맞는 모든 분배를, 비슷한 분배는 차이가 0 또는 1인 양쪽 배치를 인정한다. 총량 1은 한 차 사용을 허용한다.
- 총합은 맞아도 물건 종류별 수량이 틀리면 완료되지 않으며, 실은 물건을 그대로 유지하여 직접 수정할 수 있다.
- 열 개 묶기·풀기·묶음 이동·낱개 이동·되돌리기·처음 상태 복원이 전체 물체 수를 보존한다.
- `CHECK`로 배달을 시작한 후 이동/다시 확인이 배달 상태를 중복 변경하지 않으며, `FINISH`는 완료 기록을 한 번만 만든다.
- 배달 도중 저장본은 실은 물건을 보존한 선택 상태로 돌아오고, 완주한 저장본은 완료 상태를 보존한다. 잘못된 위치·누락 ID·중복 묶음 원소·가짜 완료 상태를 검사했다.
- seed와 생성 인자를 같게 주면 같은 미션을 얻는다.

## 발견하고 수정 확인한 사항

1. **저장 복원 후 묶음 ID 충돌:** `bundle-10000`이 들어 있는 유효 수량 저장본을 복원한 뒤 또 묶으면 같은 ID가 생겨 상태가 무효가 되었다. 구현자가 복원 시 그룹 ID를 재발급하도록 수정했고, 같은 재현 케이스가 독립 검사에서 통과했다.
2. **배달 물건과 맞지 않는 동물 반응:** 토끼가 장난감도 받을 수 있는데 “나눠 먹을게”라고 답했다. 물건 종류에 관계없이 성립하는 문장으로 바뀐 것을 소스에서 확인했다.
3. **남은 물건의 반복성:** 모든 종류에 재고가 요청량보다 3개 더 있어 5세 결과의 남은 수가 늘 같았다. 구현자가 5세 여유 재고를 seed에 따라 2~6개로 바꿨다. 최신 모델에 동일 독립 검사를 다시 실행해 600미션·19,141행동·260분배 통과를 확인했다. 검사 자체는 고정 여유분을 정답으로 사용하지 않는다.

## 수학·놀이 설계 판단

연령은 높은 수량의 접근 권한을 제한하지 않는다. 4세에서도 11~15, 16~20, 21~30 범위를 선택할 수 있고, 5세의 두 종류, 6세의 묶음과 낱개, 7세의 여러 분배 해법이 별도 놀이 방식으로 존재한다. 같은 총량을 다른 방식으로 표시해도 실제 고유 ID의 위치만 세기 때문에 묶음 모양과 실제 물체 개수가 어긋나지 않는다.

이 구조는 계획서의 “연령 UI와 도전 수량을 분리” 및 “숫자 버튼이 아닌 실제 물건을 옮겨 요청량 만들기” 계약에 맞는다. 완료 횟수로 학습 능력을 판정한다는 주장은 하지 않는다. 유아가 실제로 수량 그림을 이해하는지, 혼자 실수를 고치는지, 다시 놀고 싶어 하는지는 모델 검사로 확인할 수 없다.

## 실제 조작과 별도 검수

독립 검수자는 공유 Chrome의 공개 메뉴에서 4·5·6·7세 각 세 친구의 주문을 끝까지 배달했다. 5·6·7세에서는 11~15개 도전을 직접 선택하여 11·12·13·14·15개의 실제 물건을 담았다. 종류별 수량 오답과 분배 조건 오답을 수정하고, 6세 묶기·풀기·되돌리기와 주문 사이 보존, 7세 같은 12개 주문의 10+2 및 6+6 두 해법 재도전까지 확인했다. [실제 조작 기록과 화면 증거](post-office-browser-independent.md)를 별도 보존했다.

이 브라우저 결과는 모델 검사와 독립된 UI 검증이다. 360×640 프레임에서는 실제 클릭·스크롤로 창고·짐칸·그림 도움·출발 버튼을 검수했다. 16~20 수량과 세로·가로, 바깥 드롭은 통합 담당자의 별도 실제 조작 기록, TTS·이미지·저장 실패 및 합성 pointercancel은 구현 담당자의 별도 fixture 결과를 확인해야 한다. 실제 휴대폰·실제 손가락·아동 관찰·음성 실청취는 수행하지 않았다.

## 재실행

```sh
node scripts/qa-number-post-office-independent.cjs docs/qa/number-post-office-model-results.json
```

모델이 바뀌면 기존 PASS를 재사용하지 않고 이 명령을 다시 실행해 결과의 모델 SHA-256을 갱신한다.
