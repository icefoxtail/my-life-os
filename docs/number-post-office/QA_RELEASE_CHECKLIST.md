# 숫자 배달 우체국 — 출시 검수 장부

아래는 구현 전 고정한 검사 범위이다. 실행하지 않은 항목은 **미검증**으로 남긴다. 코드 검사, 실제 Chromium 조작, 합성 실패 입력, 실제 휴대폰 검증은 서로 다른 증거다.

- 4·5·6·7세 각각 세 주문을 완료하고 결과/다시/나가기를 확인
- 4세에서 11·15·20·30개 수량 주문 접근, 실제 싣기와 내리기
- 과다·부족·다른 종류·두 차 분배 조건 오류 후 직접 수정
- 1~30 범위의 ID 수량·묶기/풀기·되돌리기 불변식
- 원본 ID 중복·유실, 배달 중 중복 완료, 빠른 다음 버튼 입력 방지
- 마우스 드래그/바깥 드롭/합성 터치/pointercancel/blur/회전
- 360×780 세로, 844×390 가로, 태블릿, 데스크톱의 주요 버튼과 물건 크기
- 수량 20/30에서도 페이지로 나누어 같은 크기의 낱개 유지
- 새로고침/다른 놀이/모드·수량 범위 왕복/손상·차단 저장
- 음성 실패/음소거/그림 시범/이미지 실패 대체
- 웹 페이지의 공개 메뉴 연결, service worker의 신규 필수 자산
- 실제 iOS·Android·음성 실청취·아동 관찰: Chromium 시뮬레이션과 분리하여 보고

운영 main 병합 SHA와 Pages 재확인은 통합 담당자가 기록한다.

## 증거 위치

| 범위 | 증거와 경계 |
|---|---|
| 독립 수량·상태 검증 | [독립 검수 보고서](../qa/post-office-independent-review.md), [실행 결과 JSON](../qa/number-post-office-model-results.json). 600개 미션·19,141회 상태 행동·260개 분배. 모델 SHA가 바뀌면 재실행 필요 |
| 독립 실제 브라우저 | [브라우저 조작 기록](../qa/post-office-browser-independent.md). 완료·중단·미실시를 각각 기록 |
| 실패·복귀 재현 | [개발용 하네스](../../scripts/qa/post-office-failure.html), [실제 Chromium 실행 기록](../qa/post-office-failure-browser.md). 합성 입력 7건 통과, 이미지 27개 대체와 음성/저장 실패 안내 표시, 같은 환경의 당근 14개 배달 완료. 합성 입력과 실제 기기 결과를 분리 |
| 기존 저장이 남은 쓰기 실패 | [별도 저장 경합 회귀](../qa/storage-write-failure-review.md). 읽기는 성공하고 쓰기만 거부되는 경우 우체국의 최신 3개 상태와 그림판의 최신 PNG·도안 색이 같은 페이지 재진입에서 유지됨. Node 모의 저장 검증 |
| 자산 정적 검사 | 16개 로컬 SVG의 XML 파싱, 명세 viewBox 일치, 외부 이미지 의존 없음 확인. 보이는 경계는 아직 실측값으로 기록하지 않음 |
| 실제 휴대폰·아동 관찰 | iOS/Android 실제 기기, 스피커 음질, 시현이의 독립 조작은 현재 증거 없음. Chromium 및 합성 입력 결과로 대체하지 않음 |

UI의 문법 검사(`node --check js/games/number-post-office.js`)와 개발 하네스의 인라인 스크립트 문법 검사를 수행했다. 출발·수령·다시하기의 실제 동작, 레이아웃, 배포 여부는 해당 브라우저 보고서와 통합 담당자의 최종 검수 기록을 따른다.
